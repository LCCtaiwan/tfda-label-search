# 人工同義詞審查與發布

人工同義詞只幫助使用者用另一個詞找到相同文字候選，不代表兩個醫療概念永遠相同，也不代表藥品造成某個症狀。

正式設定檔是 `config/synonyms.json`。未經藥師或專案負責人審查，不可把 `reviewed` 改成 `true`。

## 格式

```json
{
  "schema_version": 1,
  "entries": [
    {
      "terms": ["測試詞甲", "測試詞乙"],
      "reviewed": false
    }
  ]
}
```

草稿確認後，才補上以下三個欄位：

```json
{
  "terms": ["測試詞甲", "測試詞乙"],
  "reviewed": true,
  "reviewer": "審查人姓名或負責角色",
  "reviewed_at": "2026-09-15",
  "note": "核准範圍或需要注意的差異"
}
```

上面只是格式範例，不是正式醫療同義詞，不應直接加入正式設定。

## 必須通過的規則

- 每組 2 到 20 個詞；每個詞 2 到 80 個字元。
- 詞內不可有空白、逗號或分號，因為這些字元在搜尋欄代表不同查詢詞。英文片語請直接用 AND 欄的多個詞搜尋。
- 全形／半形及英文大小寫正規化後，不可在同組重複。
- 同一個詞不可出現在兩個已核准群組，避免搜尋方向不明。
- `reviewed: true` 必須有 100 字元內的審查人或角色，以及真實的 `YYYY-MM-DD` 日期。
- `note` 可省略；若填寫，最多 500 字元。
- `reviewed: false` 的草稿可留在原始設定，但建置時不會複製到公開網站。

## 審查步驟

1. 先以 `reviewed: false` 建立草稿，不加入病人資料。
2. 藥師逐詞確認概念、範圍及可能造成的錯誤召回。
3. 核准後填入審查人、日期與必要說明，再改成 `reviewed: true`。
4. 執行 `npm run validate:synonyms`。
5. 執行 `npm test`、`npm run prepare:e2e` 與 `npm run test:e2e`。
6. 檢查建置後的 `site/data/synonyms.json`；它只能含已核准群組。

格式錯誤、缺少審查證據或詞組衝突時，Pagefind 建置與正式部署都會停止。第一版正式詞表目前仍為空，等待藥師核准，不以測試詞冒充正式內容。
